# TaskFlow — Database Plan

## Engine & location

- SQLite for development and tests: `backend/database/database.sqlite`.
- Schema managed exclusively via Laravel migrations in `backend/database/migrations`.
- Apply with `./bin/artisan migrate`; seed with `./bin/artisan migrate --seed`.

## Entity diagram

```
User (1) ──── (N) Project
User (1) ──── (N) Task
Project (1) ─ (N) Task
User (1) ──── (N) Comment
Task (1) ──── (N) Comment
```

## Tables

### `users`

| Column              | Type      | Notes                            |
|---------------------|-----------|----------------------------------|
| id                  | bigint PK |                                  |
| name                | string    | required                         |
| email               | string    | unique, required                 |
| email_verified_at   | timestamp | nullable                         |
| password            | string    | hashed                           |
| remember_token      | string    | nullable (Laravel convention)    |
| created_at/update_at| timestamps|                                  |

### `projects`

| Column      | Type      | Notes                            |
|-------------|-----------|----------------------------------|
| id          | bigint PK |                                  |
| user_id     | FK users  | cascade on delete                |
| name        | string    | required                         |
| description | text      | nullable                         |
| timestamps  |           |                                  |

### `tasks`

| Column      | Type      | Notes                            |
|-------------|-----------|----------------------------------|
| id          | bigint PK |                                  |
| user_id     | FK users  | cascade on delete                |
| project_id  | FK projects | nullable, adds later (`add_project_id_to_tasks_table`) |
| title       | string    | required                         |
| description | text      | nullable                         |
| status      | string    | default `pending`                |
| priority    | string    | default `medium`                 |
| due_date    | date      | nullable                         |
| timestamps  |           |                                  |

### `comments`

| Column      | Type      | Notes                            |
|-------------|-----------|----------------------------------|
| id          | bigint PK |                                  |
| task_id     | FK tasks  | cascade on delete                |
| user_id     | FK users  | cascade on delete                |
| body        | text      | required                         |
| timestamps  |           |                                  |

### Laravel/built-in tables (generated by framework packages)

- `password_reset_tokens` — from users migration.
- `sessions` — database-session driver (`SESSION_DRIVER=database`).
- `cache` / `cache_locks` — `CACHE_STORE=database`.
- `jobs` / `job_batches` / `failed_jobs` — `QUEUE_CONNECTION=database`.
- `personal_access_tokens` — Sanctum.
- `oauth_auth_codes`, `oauth_access_tokens`, `oauth_refresh_tokens`, `oauth_clients`, `oauth_personal_access_clients`, `oauth_device_codes` — Passport.

## Relationships (Eloquent)

- `User hasMany Project`, `User hasMany Task`, `User hasMany Comment`
- `Project belongsTo User`, `Project hasMany Task`
- `Task belongsTo User`, `Task belongsTo Project` (nullable), `Task hasMany Comment`
- `Comment belongsTo Task`, `Comment belongsTo User`

## Field value conventions

- `tasks.status`: `pending` (default), plus any string used by the app (e.g. `in_progress`, `done`) — free-form string, no DB constraint.
- `tasks.priority`: `medium` (default), free-form string.
- Timestamps are Laravel defaults across all tables.

## Development notes
